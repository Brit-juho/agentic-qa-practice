# AGENT-GUIDE.md

책 *에이전틱 코딩* Tutorial 22(p310~316) — *합의 기반 코드 리뷰*의 핵심을 모임 중 책 안 펴고도 작업 가능하도록 정리.

## 1. 왜 합의 기반인가

사람 한 명이 *보안 + 성능 + 테스트 + 아키텍처* 네 관점을 동시에 깊이 있게 보기는 어렵다. 단일 리뷰어의 한계를 인정하고:

- **역할 전문화**: 각자 한 가지만 깊이 본다
- **합의 종합**: 여러 결과의 *중복 병합 / 충돌 해결 / 우선순위 / 차단 여부* 까지

이게 책의 진짜 인사이트. 4명 리뷰의 *합*이 아니라 *종합 단계*가 핵심이다.

## 2. 4개 전문 리뷰어 + 1개 종합자

### 보안 리뷰어 (security-reviewer) — 호스트 샘플 제공
SQL 인젝션, XSS, 인증 결함, 안전하지 않은 구성, 기타 OWASP Top 10. 줄 번호 + 심각도 + 수정 제안.

### 성능 분석가 (performance-analyst) — **멤버 작성**
알고리즘 비효율, DB 쿼리 (N+1 등), 누락된 캐싱, 동기 블로킹, 리소스 누수. 영향 추정 + 최적화 제안.

### 테스트 커버리지 리뷰어 (test-coverage-reviewer) — **멤버 작성**
신규 기능 커버리지, 엣지 케이스, 테스트 품질, 통합 테스트 필요성. 추가할 구체 테스트 케이스.

### 아키텍처 가디언 (architecture-guardian) — **멤버 작성**
설계 원칙 위반, 결합도/응집도, 기존 코드 구조와의 일관성. 본 레포는 `docs/ARCHITECTURE.md`가 기준이다.

### 합의 종합자 (consensus-synthesizer) — 호스트 샘플 제공 (통제 변수)
4개 결과를 *통합 보고서*로. 4가지 의무:
1. **중복 병합** — 같은 이슈를 여러 리뷰어가 다르게 표현 → 하나로
2. **충돌 해결** — 예: 보안 vs 성능 충돌 → 명시적 판단 기록
3. **우선순위** — Critical / High / Medium / Low
4. **차단 여부 라벨** — Blocking / Non-blocking 모든 이슈에

## 3. 6단계 워크플로우 (책 p311~314)

| 단계 | 활동 | 본 워크숍에서 |
|---|---|---|
| 1 | 에이전트 역할 정의 | `.claude/agents/` 파일 5개 |
| 2 | 보안 리뷰 수행 | `/consensus-review` 내부 자동 |
| 3 | 성능 리뷰 수행 | 〃 |
| 4 | 테스트 커버리지 리뷰 | 〃 |
| 5 | 아키텍처 리뷰 | 〃 |

본 워크숍은 책의 수동 5번 던지기 대신 **슬래시 커맨드 한 번**으로 6단계를 모두 굴린다.

## 4. 멤버 에이전트 작성 팁

### 자기 도메인 경험을 녹여라
*책 그대로 베끼지 마라*. 본인이 코드 리뷰하면서 *자주 마주친* 문제 유형을 검사 기준에 넣어라. 멤버마다 다른 에이전트가 나와야 산출물의 가치가 살아난다.

### 입력 / 출력 명세 분명하게
- 입력: 무엇을 받는가 (`git diff`? 특정 파일? 전체 코드?)
- 출력: 어떤 *구조*로 응답하는가 (이슈 목록? 표? Markdown 섹션?)

### 너무 넓지 않게
한 에이전트가 *한 가지*만 본다. 성능 에이전트가 보안도 보면 합의 종합 단계에서 충돌만 늘어난다.

### 분량 30~80줄
너무 짧으면 검사 기준 약함, 너무 길면 *역할이 넓다*는 신호.

## 5. 산출물 양식 (Executive Summary)

종합자가 생성하는 통합 리포트는 다음 구조:

```markdown
# 통합 코드 리뷰 리포트

## Executive Summary
- 결정: Approve / Request changes / Block
- 총 이슈: N개 (Critical X / High Y / Medium Z / Low W)
- 차단 이슈: N개

## Critical Findings
### [#1] {제목}
- 발견자: Security Specialist / Performance Analyst / ...
- 위치: 파일:줄번호
- 이슈: ...
- 수정 방향: ...
- 차단 여부: Yes / No

## High Priority
...

## 충돌 해결 기록
- (리뷰어 간 의견이 갈렸던 항목과 우선순위 결정)

## 다음 이터레이션 후보
- (Non-blocking이지만 다음에 다룰 항목)
```
